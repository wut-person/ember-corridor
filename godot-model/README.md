# 余烬回廊 · 角色 2D 矢量骨骼模型（Godot 4）

用 **Godot 4.7 + GDScript 程序化生成**的 2D 矢量骨骼角色，对应游戏 `js/data/clothing.js`
里的前两套外观（余烬剑姬 / 铁壁游侠）。**不依赖任何图片素材**：所有几何是代码生成的
`Polygon2D`（50 个部件），绑定在 `Skeleton2D` 的 9 根骨骼上，动作由代码插值驱动。

> 这是**独立工程**，与纯 HTML5 的 2D 像素游戏本体互不影响。

## 三、建模规格

**坐标系**：脚底中心为原点，向上为负（-Y），1 单位 = 1 像素；屏幕缩放 `S = 5.9`，
角色在 1440×900 下实测高约 **399 px**（占视口 44%）。

**纵向布局（建模单位）**

| 部位 | 范围 | 占身高 |
| --- | --- | --- |
| 发髻顶 | -74 | — |
| 头顶 → 下巴 | -66 → -54（头高 12） | 16% |
| 肩 | -65 | — |
| 躯干 | -65 → -42 | 31% |
| 腰 / 髋 | -43 → -32 | 15% |
| 腿（大腿 + 小腿 + 靴） | -32 → 0 | **43%** |

**骨骼（9 根）**

```
hips(-32)
├─ torso(-65) ── arm_b(-65, x-6.8)   [肩→手 -68..-40]
│             ├─ arm_f(-65, x+6.8)   [持剑手]
│             └─ head(-64.3)          [头 / 发 / 五官 / 胡须]
├─ leg_b(-32.4, x-2.6) ── leg_b_shin(-18)   [小腿 + 靴子]
└─ leg_f(-32.4, x+2.6) ── leg_f_shin(-18)
```

**部件（50 个 `Polygon2D`）**：头 / 下颌 / 双眼 / 双瞳高光 / 双眉 / 鼻 / 嘴 / 头发（波波头或发髻 + 鬓角）/
胡须（男）/ 躯干上下段 / 胸甲高光 / 领口 / 下摆布 / 四条皮带 / 髋 / 腰带 / 腰带扣 / 披风领 / 披风扣 /
披风下摆（男为宽斗篷 4 件）/ 双肩甲 / 双臂 / 双护腕 / 双手 / 双腿大腿 + 小腿 + 靴 + 鞋底 + 靴口 + 腿甲片 /
长剑（握把 + 护手 + 剑身 + 刃口高光）/ 腰间短剑（女）/ 背负长弓（男）。

**动作（8 个，全部由代码插值驱动骨骼）**

| 动作 | 关键点 |
| --- | --- |
| 待机 | 呼吸起伏 + 腰部微摆 + 手臂随呼吸轻晃 |
| 奔跑 | 双腿 36° 交替摆动、小腿回勾 50°、手臂反向摆 30°、躯干前倾 |
| 跳跃 | 收腿 + 手臂上摆，髋部随速度起伏 |
| 连招①平斩 | 手臂从前摆 -58° 扫到 +62°，躯干反向扭转 |
| 连招②上挑 | 手臂从 +78° 挑到 -104°，髋部下沉再弹起 |
| 连招③下劈 | 手臂从 -118° 砸到 +74°，髋部前送 8° |
| 受击 | 后仰 16°、髋部后移、手臂回收 |
| 下蹲 | 髋部下沉 11 单位、大小腿折叠（-52° / -44°） |

## 四、当前状态（截至本次保存）

**已完成**

- 工程可正常打开与运行，GDScript 解析零报错
- 两套外观（余烬剑姬 / 铁壁游侠）的完整几何与配色数据，可从游戏 `G.LOOKS` 一一对应
- 9 根骨骼 + 50 个部件的装配管线跑通（`rest` 静置变换已正确设置，部件不再错位）
- 8 个动作的姿态驱动 + 剑的独立握持角度控制
- 无头批量出图（10 张）+ 自动裁切放大工具
- 量化诊断与部件调试视图两套排查工具

**已定位并修复的坑（供后续参考）**

1. 骨骼局部坐标必须减去**父骨骼的完整绝对坐标（x 与 y 都要）**，只减 y 会让手臂/腿纵向摞在一起
2. `Polygon2D` 挂到 `Bone2D` 上之前必须设置 `bone.rest = bone.transform`，否则整体错位
3. GDScript 里自定义方法**不能叫 `_set`**（与 `Object._set(StringName, Variant) -> bool` 签名冲突）
4. 用正则批量重映射坐标区间的做法反复出错 —— **几何数据应当直接写明确坐标**，不要二次变换

**已知不足（下一步建议）**

- 手臂摆动后与肩甲的接缝在个别角度有轻微错位
- 披风 / 斗篷目前是刚性多边形，没有骨骼，跑动时不会飘动（建议加 2~3 根布料骨骼）
- 长剑目前是刚性图元组合，握持角度靠 `weapon_rot` 手动调，缺少握点对齐
- 动作是代码插值，尚未转成 `AnimationPlayer` + `AnimationLibrary`（转成后可在编辑器里可视化调帧）
- 尚无「2D 骨骼 → 逐帧 PNG / 精灵图集」的导出脚本

## 五、与游戏本体（HTML5）的关系

现在的 2D 游戏用 `js/core/sprites.js` 在 Canvas 上逐像素绘制角色。本工程的模型**尚未接入游戏**，
两者目前是并行关系。若要接入，可选三条路：

1. **导出精灵图集**：在 Godot 里按帧渲染成 PNG 序列（或 `SpriteFrames`），再由 `sprites.js` 加载
2. **把骨骼数据搬回 JS**：把本文的骨骼 / 部件 / 动作数据导出为 JSON，在 Canvas 里用同一套插值逻辑绘制
3. **保留 Godot 版本单独迭代**：先把模型在 Godot 里打磨到位，再决定接入方式
